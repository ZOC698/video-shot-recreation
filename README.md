# 视频拉片与复刻 · Video Shot Recreation

[中文](README.md) | [日本語](README.ja.md) | [English](README.en.md)

一个提供中文、日本語、English 文档的 Codex Skill：从参考视频分析、动作量化，到角色替换、完整提示词和成片对比。默认使用用户的语言交付；指定提示词语言时遵从指定。

它服务于“保留这个镜头，换成我的角色”，也服务于“为什么这一版动作不对”。不限定视频模型，不要求先提交验证案例。第一版是纯 Markdown 方法包，没有额外脚本、自动生成服务或媒体素材。

## 能做什么

- 按镜头或逐帧分析画面，说明构图、动作、运镜、特效和叙事作用。
- 量化敌人数量、同时攻击者、脉冲轮次、时间间隔、动作耗时与位移。
- 保留用户选定镜头，把角色、造型或场景改成指定素材。
- 对比原片和生成版本，区分可见差异、提示词缺失与原因假设。
- 根据需求写完整提示词、简单位置图说明或剪辑建议。

**核心立场：量化与因果并用，用户目标优先。** 数字不是禁区，社区经验也不是硬性模型参数。角色替换不能擅自变成故事重写。

## 使用示例

```text
使用 $video-shot-recreation 分析这个视频的5—12秒。
逐帧检查起飞到命中的动作，画面配合描述；没听到的声音不要猜。
```

```text
保留参考片的关键构图、镜头顺序和撞入入口的结局。
主角换成我的角色图，给30秒完整提示词。
把同屏敌人、同时攻击者和每轮脉冲分别量化。
```

```text
对比原片、第一版和第二版，按同一动作事件对齐。
重点看第二版为什么变成跑步，以及结尾为什么像推人。
只给诊断和局部修法，不重写整段。
```

这些是调用方式，不是已经验证成功的生成案例。

git clone https://github.com/ZOC698/video-shot-recreation.git ~/.codex/skills/video-shot-recreation

## 为什么这样设计

在实际协作中，常见的问题不是缺少“震撼、超高速”等形容词，而是：

- 新素材被误套进上一部片子的剧情。
- 怪物铺满背景，却只有一两只参与攻击。
- 只写“密集脉冲”，未定义来源、轮次与重叠。
- 冲撞被写成持续推挤；飞行被演成跑步。
- 角色换了新披风，提示词却保留旧版无披风约束。
- 镜面、折射和巨大尺度缺乏几何关系，成为装饰效果。
- 抽取了所有帧，却没有真正审阅全部，仍声称逐帧完成。

本 Skill 将这些经验写成诊断与选择方法，不将某一条片子的数字或剧情变成通用模板。用户曾反馈明确量化敌人和脉冲后效果提升；这是创作反馈，不是受控实验或跨模型成功率证明。

## 量化示意

> 创作目标：左右各3个发射源，每源每轮1发，一轮共6发；第二轮比第一轮晚0.4秒开始，每发在画0.6秒。主角在两轮重叠时侧移，落空脉冲在身后路面结束。

这里分别锁定来源、数量和时间关系。它不是所有作品的最佳参数，也不是官方 API。实际分析须标出实测、估计和目标，遮挡时可以给下界或范围。

## 边界与依赖

- 方法文档不需要 FFmpeg；自动读取元数据和抽帧时可用 FFmpeg/ffprobe，镜头候选检测可选 PySceneDetect。工具不可用时明确可检查的范围。
- 正常速度审片、连续帧检查和听音承担不同任务。没有音频感知能力时不声称核听。
- 不自动提交视频生成、不自动上传素材、不自动公开私人文件；这些需当前任务的明确授权。
- 完整提示词不保证视频模型逐帧执行。需要时可以局部修改、分段生成或剪辑，但这些不是使用本 Skill 的强制门槛。
- 本仓库只发布原创整理的文档；不附用户私人视频、角色图、对话记录或第三方影视帧。
